# 性能设计与调优

统计插件最容易犯的错，是把统计的代价转嫁给访客。本插件的全部设计都围绕一条线：**请求内不做任何可能变慢的事**。

## 请求内做了什么、不做什么

| 做 | 不做 |
|---|---|
| 读 opcache 里的编译产物 | 查数据库（一次都没有） |
| 哈希查表判名单 | `session_start()`（内核实现要 open + flock + close） |
| 一次 `strpbrk` 预筛 | DNS 反查（`gethostbyaddr` 没有超时参数） |
| 命中预筛时才跑正则 | 查 IP 库（除非开了地区规则，或本请求已判定为攻击） |
| 响应发出后追加一行日志 | 渲染模板、写 Redis 大对象、发通知 |

日志写入在 `fastcgi_finish_request()` 之后 —— 浏览器已经拿到完整响应了，这部分耗时访客感知不到。

## 实测数字

在开发站（PHP 8.0.26）上的单项测量：

| 项 | 耗时 |
|---|---|
| WAF 逐条正则匹配（36 条全跑） | **7.2 µs** |
| CC 限频计数一次（文件驱动） | **41.9 µs** |
| 蜘蛛识别（一条合并正则） | **约 3 µs** |

绝大多数正常请求**根本不会跑到第 8 步**：`strpbrk` 预筛在整个请求里找不到 `' " < > ( ) \ ; | \` $ * %` 任何一个字符就直接结束，正则一条都不执行。

> 曾经试过把 36 条正则合并成几个大块来减少 `preg_match` 调用次数，实测反而**慢 2.9 倍**（20.8 µs vs 7.2 µs）：PCRE 对巨型交替式的优化远不如对短表达式好，而且合并后没法在第一条命中时提前退出。这个优化已经撤掉了，别再合。

## 采集：8 分片 spool

```
请求 A ─┐
请求 B ─┼─► 按 PID 散列到 s0..s7.log，各写各的，无锁竞争
请求 C ─┘
              │ 每 2 秒
              ▼
        原子 rename 封存 ──► 入库任务批量读 ──► 一次事务写完
```

- **分片**是为了避免所有并发请求抢同一个文件的追加位置。8 片在实测中足够，再多收益递减。
- **`rename` 是原子的**（同分区内），封存瞬间写者转向新文件，读者拿到的永远是完整文件，两边都不用加锁。
- **批量入库**：一次任务把几百上千行合并成少数几条 SQL，摊到每个请求上的数据库开销接近于零。

线程管理器不在时，网页请求会用 `O_EXCL` 抢一个租约来接力入库 —— 同一时刻只有一个请求在干这活，其余照常返回。延迟从 2 秒变成约 15 秒（可调），但**不丢数据**。

### 洪峰自动降级

写日志本身也可能变成负担。两个触发条件，任一满足就把采集切到**精简模式**：

- 最近一轮的入库速率超过「洪峰降级阈值」（默认 2000 行/秒）
- 单个 spool 分片堆到 32 MB

精简模式下每行从约 260 字节掉到约 40 字节：**PV、攻击数、TOP IP 依然精确**，只丢页面 / 来源 / UA 明细。状态写进 `state.php`，2 秒内全站 PHP-FPM 进程通过 opcache 感知，不用重启也不用广播。

恢复要满足两个条件：速率掉到阈值的 **60% 以下**，且已经处于精简模式至少 60 秒。这两个迟滞条件是为了避免流量在阈值上下抖动时，模式跟着来回切 —— 每次切换都要写一次文件并让 opcache 失效。

## IP 库：62 MB 文件怎么查得快

三件事：

1. **绝不整文件读入内存。** 持久 `fopen('rb')` + 按需读 4 KB 块。
2. **块级 LRU 缓存**，每进程上限 64 块。MMDB 的搜索树查询总是从根部开始，局部性极好 —— 加了这个缓存后，单次查询的 `fread` 次数从大约 32 降到 8 左右。
3. **惰性键解码。** City 库的一条记录含几十种语言的地名，插件只解 `country / subdivisions / city / continent` 的 `zh-CN` 和 `en`，其余整段跳过不解析。

外面还包了三级缓存：进程内 → 持久缓存（Redis 或文件）→ 实查。持久缓存的 key 用 **MMDB 实际返回的命中网络前缀**，不是固定的 /24：既保证正确（有些网段就是按 /16 划的），又能把几千万个 IP 折叠成几千个网络条目。

**但最大的优化是请求内根本不查**：没配地区规则的站点，正常请求的热路径永远不会碰 IP 库。只有开了地区规则、或者本请求已经被判定为攻击（要在告警里显示归属地）时，才会在请求内触发查询。

地域统计要的归属地是**入库时**补的：后台任务把一批日志里出现过的 IP 去重后一次查完，成本摊到几百上千行上，跟访客的响应时间完全无关。查不到的 IP 也不会被丢掉 —— 内网归到「内网」、公网查不到的归到「未知」，这样地域页的合计永远和 PV 对得上。

## 限频计数器

优先 Redis，退回文件。两种都不用全局锁。

**Redis 路径**用自建连接，`SERIALIZER_NONE`。不能复用站点那条共享连接 —— 它是 `SERIALIZER_PHP`，`incr` 出来的值会被序列化成字符串，语义直接错掉。

**文件路径**是每个 IP 一个 **492 字节定长文件**：60 个秒桶 + 60 个分桶的环形缓冲，定长意味着可以直接 `fseek` 到目标位置改，不用读改写整个文件。**故意不加 flock** —— 极端并发下最坏结果是丢几个计数，而全局单文件加锁在被攻击时本身就会变成 DoS 点。

## 调优建议

### 小站（日 PV < 5 万）

默认配置直接用，什么都不用改。

### 中站（日 PV 5～50 万）

- 装 Redis 插件，限频计数器会自动切过去。
- 明细保留可以从 30 天降到 14 天，磁盘省一半。

### 大站（日 PV > 50 万）

- **打开「明细表按天分区」**。清理旧数据从 `DELETE` 变成 `DROP PARTITION`，秒级完成、不锁表。
- 明细采样率调到 20～50。**聚合数据仍然精确**，只有逐条明细按比例抽样。
- 「洪峰降级阈值」按自己的峰值 QPS 设。默认 2000 请求/秒，超过就自动切精简采集（见下）。
- 分钟级时序保留从 3 天降到 1 天。
- CC 阈值按实际流量抬高，默认值（10 秒 60 次）对高频 AJAX 站点偏紧。

### 被攻击时

1. 防火墙切**严格模式**。
2. 攻击源集中的话，直接按网段或地区加黑名单 —— 名单匹配比正则便宜一个数量级，能在第 6 步就结束。
3. 全站过载保护会自动介入：白名单、已验证蜘蛛、已登录会员照常，其余阈值收紧到 1/3。
4. 顶不住就上 CDN。应用层 WAF 挡得住 CC，挡不住把带宽打满的流量攻击 —— 那是另一个层面的事。

## 用了 CDN 一定要配受信代理

用了 CDN 或反向代理之后，`REMOTE_ADDR` 是 CDN 的 IP，真实客户端 IP 在 `X-Forwarded-For` 之类的头里。**这个头是可以随便伪造的。**

如果配置成"从代理头取客户端 IP"却没填受信代理清单，任何人都能在请求里塞一个假 IP —— 封禁封不到真人，限频计数分散到无数个假 IP 上，整套防护形同虚设。面板检测到这个组合会显示红条警告。

正确做法：设置 → 系统 → 填上 CDN 的回源网段。只有来自这些网段的请求，代理头才会被采信。

## 关掉内核的 request_log

内核自带 `kernel/Util/RequestLogger.php`，往 `runtime/request/` 写请求日志。本插件启用后这份数据是重复的，关掉能省一次磁盘写。

## 面板本身的性能

- 图表和表格**懒加载**：切到哪个页签才请求哪个页签的数据。
- 切走时 `dispose()`：ECharts 实例、定时器、`MutationObserver`、`AbortController` 全部清理。pjax 反复切页不会累积泄漏。
- 实时页 3 秒轮询，**页面切到后台时自动降到 30 秒**（`document.hidden`）。
- 所有排行榜直接命中 `wm_agg` 的 `(day, dim, pv)` 索引，不做实时聚合。
