# 网站监控统计

> 实时访问监控（PV / UV / IP / 请求 / 蜘蛛）、流量与来源分析、地区归属，外加一套针对本程序深度定制的安全防火墙（SQL 注入 / XSS / 路径穿越 / 扫描器 / CC / 登录爆破）。
> **每个请求零 SQL、零阻塞**：判决只读内存里的编译产物，日志在响应发出去之后才落盘。

## 5 分钟上手

1. **启用插件**：通用插件 → 网站监控统计 → 启用。首次启用会自动建 22 张表，并把**你当前的 IP 写进永久放行清单**（防锁死第一道保险）。
2. **装并启用「线程管理器」**（强烈建议）：入库、汇总、清理、蜘蛛反查、IP 库周更全部由它的常驻任务承担。没有它插件也能跑，但统计会由网页请求接力入库（延迟约 15 秒），且蜘蛛反查与 IP 库自动更新不可用。
3. 打开左侧菜单 **网站监控** 面板 → 随便刷两下前台 → 「实时」页应当立刻看到自己的请求流与在线数。
4. **下载 IP 库**：设置 → 地区 → 「立即更新 IP 库」。约 62 MB，下完地区统计与地区规则才可用（不下载不影响其它功能）。
5. **防火墙先跑观察模式**：默认就是观察模式（只记录不拦截）。挂一两天，去「安全」页看看「本可拦截 N 次」里有没有误伤自己人；确认干净了，再到设置里切「拦截」。
6. （可选）**通知**：装了「通知中心」插件就自动可用，安全告警走它的邮件 + Telegram，发送记录也在它那边查。没装则通知功能静默关闭，其它一切照常。

> 启用本插件后，可以关掉内核自带的 `request_log`（它往 `runtime/request/` 里写日志），避免同一份数据写两遍磁盘。

## 工作原理（为什么它不拖慢站点）

```
HTTP 请求
  └─ KERNEL_INIT(0x30) ──► 防火墙判决 + 采集开始     纯内存，0 次 SQL，约 20 µs
        · 命中即 403 并结束，比内核更早，攻击流量根本进不到业务代码
  └─ …正常业务…
  └─ 响应已发给浏览器（fastcgi_finish_request 之后）
        └─► 往 spool 分片追加一行                    约 60 µs
                │
       spool/s0..s7.log ──原子 rename 封存──► 入库任务（2 秒一轮）──► 明细 + 计数 + 会话
                                                        └─► 汇总任务（60 秒）/ 日汇总 / 清理
```

三条铁律：

- **请求内绝不写库。** 所有落库都在响应之后、由后台任务批量做。
- **聚合永远精确。** spool 每个请求一行，采样只发生在 `wm_access` 明细表；PV/UV/访问次数不会因采样失真。
- **线程管理器缺席时降级但不丢数据。** 网页请求会轮流持租约把 spool 接力入库，只是延迟从 2 秒变成约 15 秒。

## 统计口径（重要）

- **PV** = 页面请求数（不含静态资源，静态资源根本不进 PHP）。
- **UV** = 去重后的独立访客，靠 `wm_seen` 表的主键 + `INSERT IGNORE` 精确计数，不是估算。
- **访问次数（会话）** = 30 分钟无活动即算一次结束，可在设置里改。
- **跨天区间不显示 UV。** `SUM(每日UV)` 会把连续几天都来的人重复计算，是假精确。多天区间只显示「访问次数」；确实要跨天精确 UV，去「访客」页用会话表统计。
- **在线** = 最近 5 分钟内有过 PHP 请求的访客，不需要前端心跳（静态资源不过 PHP，每个 PHP 请求基本等于一次真实交互）。
- **蜘蛛默认不计入 PV/UV**，单独在「蜘蛛」页统计；想合并计数可在设置里打开。
- **搜索词大多是空的**，这是正常现象：主流搜索引擎早就对 referrer 加密了，能解析出来的只有零星几个小引擎。
- **地域统计不会漏人**：内网地址归到「内网」，公网但 IP 库里查不到的归到「未知」，所以地域页的合计跟总访问次数永远对得上。没下载 IP 库时整个地域维度为空，面板会提示你去下载。

## 访客身份识别

不调 `session_start()`（内核的 Session 每次都要 open + flock + close，0.3～1 ms，热路径付不起）。插件用自己的两个 Cookie：

- `wm_vid`：访客标识，16 位随机 + 8 位 HMAC 签名，730 天，伪造无效。
- `wm_sid`：会话标识，内含起止时间戳，为省写入做了 60 秒节流。

不吃 Cookie 的客户端（多数爬虫、隐私模式）用**当日盐指纹**兜底：指纹只在当天内有效，不跨天关联，隐私友好但也意味着这类访客每天算新人。

## 防火墙的三种姿态

| 模式 | 行为 | 适合 |
|---|---|---|
| **观察** | 全部命中只记录、不拦截，面板显示「本可拦截 N 次」 | 新装必选，先跑 1～2 天看误报 |
| **拦截** | 按规则各自的动作执行：计分 / 拦截 / 封禁 / 限速 | 确认无误伤后的日常姿态 |
| **严格** | 在拦截基础上把「计分」类规则也提为拦截，阈值收紧 | 正在被打的时候临时开 |

规则详解与全部 36 条规则清单见 [防护规则](Rules.md)。

## 五道防锁死保险

把自己关在门外是这类插件最常见的事故，所以做了五道：

1. **紧急停用文件**：在服务器上 `touch runtime/plugin/WebsiteMonitor/DISABLED`，全部防护立即停止。拦截页正文里就印着这个完整路径 —— 就算你被自己的规则挡在外面，也能照着页面上的字自救。
2. **紧急开关**：设置页的「紧急停用全部防护」按钮，等价于上一条但不用登服务器。
3. **永久放行清单**：安装时自动写入你当时的 IP，这个清单**优先于一切规则**。
4. **管理员会话豁免**：带着有效后台会话的请求整体跳过防护（默认开），并自动维护一份 30 天滚动的管理员常用 IP 白名单。
5. **保存时自锁检测**：保存任何一条会封禁你当前 IP 或你所在地区的规则时，插件会直接拒绝并告诉你原因；确实要这么干得勾选「我已了解风险」。

另外**地区规则永不作用于 `/admin/*` 和 `/plugin/*/admin/*`**，这是硬编码的，改配置也绕不过去。

## 黑白名单

规则页支持六类名单，每类都能写多种格式：

```
1.2.3.4              单个 IP（v4 / v6 都行）
1.2.3.0/24           CIDR 网段
1.2.3.*              通配
1.2.3.10-1.2.3.20    区间
CN                   国家
CN.GD                省 / 州
CN.GD.深圳市          城市
```

- **白名单优先级最高**：在白名单里的 IP 不会被任何规则拦截、不计入限频。
- **黑名单支持有效期**：填小时数，到点自动失效；填 0 是永久。
- **搜索框输入一个 IP，会把所有包含它的网段一起找出来** —— 排查「这个 IP 为什么被拦」很有用，也可以直接用「安全 → IP 检测」。
- **自动封禁单独一张列表**，由防火墙规则触发，到期自动解封，可以随时手工延长为永久或立即解封。

封禁时长走梯度：默认 5 分钟 → 30 分钟 → 2 小时 → 1 天 → 7 天，第 6 次转永久；72 小时内没有新违规则清零重来。

## CC 防御

三个层面同时看：

| 维度 | 默认阈值 | 动作 |
|---|---|---|
| 单 IP 突发 | 10 秒 60 次 | 封禁 5 分钟 |
| 单 IP 持续 | 10 分钟 600 次 | 封禁 5 分钟 |
| 单 IP + 单路径 | 10 秒 30 次 | 429 限速，不封 |
| 全站合计 | 10 秒 3000 次 | 进入过载模式 |

**过载模式**下白名单、已验证蜘蛛、已登录会员照常访问，其余请求的阈值收紧到 1/3。已验证蜘蛛、已登录会员、支付回调路径默认豁免限频 —— 支付回调被限流会掉单，这条别关。

计数器优先用 Redis（自建 `SERIALIZER_NONE` 连接，不与站点共享的那条混用），没有 Redis 就退回**每个 IP 一个 492 字节定长文件**的无锁环形缓冲。没有全局单文件加锁那种设计 —— 被打的时候那玩意儿本身就是 DoS。

## 蜘蛛识别

- 内置 55 条签名，覆盖搜索引擎 / SEO 工具 / AI 抓取 / 社交预览 / 监控拨测 / 安全扫描六组，也可以自己加。
- 热路径只跑**一条合并正则**（约 3 µs）同时判断「已知签名」和「泛化机器人」。
- **绝不在请求内做 DNS 反查**：`gethostbyaddr()` 没有超时参数，伪造一个 UA 就能把站点拖死。反查由后台任务异步做，PTR + 正向确认双向校验，结果缓存 7～30 天。
- 反查对不上的（声称 Googlebot 但 PTR 不是 google.com）算**伪装蜘蛛**，计入攻击并从蜘蛛统计里剔除。

## 数据保留与清理

| 数据 | 默认保留 | 说明 |
|---|---|---|
| 访问明细 `wm_access` | 30 天 | 可采样、可按天分区 |
| 会话 | 30 天 | |
| 访客档案 | 180 天 | |
| 攻击取证 | 14 天 | 含用户明文输入，故意留得短 |
| 聚合报表 | 400 天 | 面板所有排行榜的数据源 |
| 分钟级时序 | 3 天 | |
| 小时级时序 | 180 天 | |
| 日级时序 | 永久 | |

明细表可以手动调采样率（默认 100 = 全量），**聚合数据不受采样影响，始终精确**。清理由后台任务每天做，也可以在设置页手动点。

流量真的打上来时还有一层**自动洪峰降级**：全站持续超过 2000 请求/秒（可调），采集自动切到精简模式 —— 每行日志从约 260 字节掉到约 40 字节，PV、攻击数、TOP IP 依然精确，只是暂时不记页面、来源、UA 明细；速率回落到阈值的 60% 以下后自动恢复（带迟滞，不会在临界点反复抖动）。单个 spool 分片堆到 32 MB 也会触发同样的降级。面板会标注当前处于精简模式。

大站建议打开「明细表按天分区」：删 30 天前的数据从 `DELETE` 变成 `DROP PARTITION`，秒级完成且不锁表。

## 通知

装了「通知中心」插件就自动接上，邮件与 Telegram 都用它的配置，发送记录也在它的面板查。可通知的事件：

- IP 被自动封禁
- CC 攻击 / 站点整体过载
- 攻击突发（10 分钟内超过 50 次）
- 后台在陌生国家登录
- 后台密码爆破
- IP 库更新失败 / 成功
- 每日统计摘要（默认关）

**三重防刷屏**：本地 30 分钟同类冷却（累计的抑制次数会一次性带出来）+ 通知中心的去重键硬约束 + 级别门槛（默认「警告及以上」）。

反过来，通知中心的安全事件页每行都有一个「封锁 IP」按钮，点了直接调本插件的 API 封人 —— 收到告警邮件后回后台一键处置，不用再去规则页手输 IP。

## 常见问题

**面板一直显示「采集积压 N 个文件」？**
线程管理器没跑。去它的面板启动守护进程；如果守护进程在跑但任务没注册，点一次「重载注册表」。

**新加了 Hook 方法但不生效？**
`runtime/plugin/hook` 是加密编译缓存。后台把插件**停用再启用**一次就会重建。

**改了模板没变化？**
清 `runtime/view/compile`。**绝对不要删 `runtime/config`**，删了整站 502。

**地区统计全是「未知」？**
IP 库没下载，或下载失败。去设置 → 地区看最后一次的结果；服务器出不了网的话，把 mmdb 文件手动传到 `runtime/plugin/WebsiteMonitor/geo/` 也行。

**为什么后台自己的访问也被统计？**
默认统计。不想要就在设置 → 采集里关掉「统计后台访问」。

**误封了自己怎么办？**
按上面「五道防锁死保险」的第 1 条，服务器上 `touch runtime/plugin/WebsiteMonitor/DISABLED`，进后台把自己加白，再删掉这个文件。

**攻击取证里会不会存到密码？**
不会。取证复用全局脱敏，`password|token|secret|sign|card|cvv` 这类字段值直接打码，Cookie 整体 `***`，而且只存命中片段前后各 64 字节，不存整个请求体。
